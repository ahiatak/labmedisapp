# Traceability & Quality Checklist: Système de Gestion LABMEDIS (Dépositaire Pharmaceutique)

**Purpose**: Validate the requirements-quality of the FEFO / lot traceability / quarantine-quality / recall domain (US4, US5, US8, US13; FR-029 to FR-044, FR-058, FR-060 to FR-062, FR-080 to FR-083, FR-092) — the highest-risk regulatory area of the spec (BPD/UEMOA compliance, success criterion #1). This is a standard-depth PR-review checklist for a peer reviewing spec.md before/during implementation.
**Created**: 2026-08-31
**Feature**: [spec.md](../spec.md)

**Note**: This custom checklist is generated by the `/speckit-checklist` command based on feature context and requirements.
**Review Ownership**: This checklist is a reviewer-owned requirements-quality review artifact. Mark an item `[x]` only when the reviewer determines the requirements-quality criterion is satisfied.
**Marker Semantics**: `[x]` means the criterion has been reviewed and satisfied for requirements quality. It does not mean implementation work is complete.

## Requirement Completeness

- [x] CHK001 Are the four independent conditions for a manual FEFO override (lot not expired, status Libéré, sufficient quantity, non-empty reason) each stated as separately testable requirements, or only bundled into a single combined scenario? [Completeness, Spec §FR-037]
- [x] CHK002 Is the quality-status state machine (En réception, En quarantaine, Libéré, Non conforme, Périmé, Détruit, En attente de libération, Suspecté falsifié) accompanied by an explicit transition matrix defining which states can move to which, or only a partial transition example? [Gap, Spec §FR-040]
- [x] CHK003 Does the spec define expected behavior for `StockLotLocation` quantities when a stock movement of type "Transfert" occurs between two locations, or does it only require the movement record itself (type/qty/date/user/locations)? [Gap, Spec §FR-038/FR-039]
- [x] CHK004 Are the required fields of a reception "constat d'écart" (discrepancy report: manquant/excédent/non commandé/endommagé) explicitly enumerated, or is only its existence required? [Completeness, Spec §US4-AC4]
- [x] CHK005 Does the spec define what happens when a quarantine location reaches capacity and a newly quarantined lot has nowhere dedicated to go? [Gap]
- [x] CHK006 Is the "unlimited retention, no purge" requirement (FR-092) explicitly reconciled against the append-only-exemption list mentioned elsewhere (e.g. login/password history), confirming traceability data (lots, movements, invoices, audit log) is never included among exempted/purgeable tables? [Consistency, Spec §FR-092]
- [x] CHK007 Are requirements defined for concurrent modification of the same lot from two different modules at once (e.g. a quality release and a sale reservation processed at the same moment), beyond the sale-vs-sale concurrency case already covered by FR-091? [Gap, Non-Functional]

## Requirement Clarity

- [x] CHK008 Is "motif obligatoire" (mandatory reason) for a FEFO derogation, a quarantine, or a non-conformity declaration defined with any minimum-content rule (e.g. non-whitespace, minimum length), or left fully open to interpretation? [Clarity, Spec §FR-037/FR-042]
- [x] CHK009 Is "quarantaine prolongée" (the FR-076 notification trigger for prolonged quarantine) quantified with a specific duration threshold, or left ambiguous? [Clarity, Spec §FR-076]
- [x] CHK010 Is the "avertissement visible" (visible warning) required when the first FEFO-proposed lot expires within 30 days defined with any concrete requirement, or is "visible" left unquantified? [Clarity, Edge Cases]
- [x] CHK011 Does the spec clarify what "chaque ligne de facture référence explicitement le lot vendu" means when a single sale-order line is fulfilled by multiple lots (split allocation across lots for one product line)? [Ambiguity, Spec §FR-058]
- [x] CHK012 Is the "document de destruction obligatoire" (US5-AC6) specific about required document type/fields, or does it only require "a document" without content requirements? [Clarity, Spec §US5-AC6]
- [x] CHK013 Is the product-category boundary that triggers the mandatory DPML authorization reference (FR-028: required for "médicaments", optional otherwise) unambiguous given the broader catalogue (réactifs de laboratoire, produits infantiles, cosmétiques, compléments, insecticides)? [Clarity, Spec §FR-028]

## Requirement Consistency

- [x] CHK014 Are the expiry-blocking thresholds at reception (FR-031: 30-day generic strict block, plus 60/90/120-day alert thresholds by category) clearly reconciled with the daily notification thresholds (FR-076: J-30/60/90/120) — is it explicit whether reception-time blocking and the daily alert job share the same per-category threshold set or use two distinct sets? [Consistency, Spec §FR-031 vs §FR-076]
- [x] CHK015 Do the quarantine/quality requirements (FR-040 to FR-043) and the customer-return disposition rule ("Quarantaine" outcome, FR-061) agree on what "quarantine" means procedurally — same state machine and same mandatory-reason rule — or are two independent quarantine concepts implied? [Consistency, Spec §FR-040 vs §FR-061]
- [x] CHK016 Is the generic "reason"/"motif" requirement used consistently across FEFO derogation (FR-037), quarantine/non-conformity (FR-042), and return disposition (FR-061), or could each context imply a different validation rule for what counts as a valid reason? [Consistency, Ambiguity]

## Scenario & Edge Case Coverage

- [x] CHK017 Does the spec define what happens when a lot already reserved by a confirmed, undelivered sale order is subsequently flagged "Suspecté falsifié"? [Gap, Exception Flow]
- [x] CHK018 Are requirements defined for near-simultaneous conflicting quality decisions on the same lot (e.g. a release and a destroy action requested in quick succession)? [Gap, Non-Functional]
- [x] CHK019 Is there a requirement covering what happens to an in-progress inventory-session freeze (US9) if a lot within its frozen perimeter is placed in quarantine or declared falsified during the freeze? [Gap, Coverage]
- [x] CHK020 Does the spec address a customer return referencing an original lot that has since been destroyed (still traceable per FR-092, but no longer physically available for "remise en stock")? [Edge Case, Gap]
- [x] CHK021 Does the spec define whether a recall search (FR-082) for a given lot number must also surface customers whose order was later returned and re-dispositioned (e.g. returned then destroyed), or only the original sale? [Gap, Spec §FR-082]

## Acceptance Criteria Quality

- [x] CHK022 Can "0% d'erreur sur la traçabilité des lots" (SC-002) be objectively measured given the current spec, or does it lack any defined audit/verification procedure to confirm the criterion is met? [Measurability, Spec §SC-002]
- [x] CHK023 Is "délai de retour" (the return-eligibility window checked in US8-AC1) quantified with a specific number of days, or left to unspecified configuration with no documented default? [Clarity, Spec §FR-060]

## Dependencies & Assumptions

- [x] CHK024 Is the documented assumption "la traçabilité est gérée au niveau du lot (et non au niveau de l'unité individuelle/numéro de série)" explicitly cross-checked against the recall requirement (FR-082, US13-AC2/3) to confirm lot-level granularity is sufficient for a full regulatory recall? [Assumption, Spec §Assumptions]
- [x] CHK025 Is the dependency between US5 (quarantine release restricted to Responsable Qualité) and US2 (roles/permissions) made explicit — does the spec name the exact permission/role gate, or only describe it narratively? [Dependency, Gap]
